Web Security Quick Reference

The 60-second mental model for CSP vs CORS vs CSRF — plus OAuth 2.0 / OpenID Connect flows and GraphQL introspection.

CSP — Content-Page Related

Defends against XSS. Think: "only load scripts from…". The standard HTTP CSP directives come from W3C/MDN: default-src, script-src, script-src-elem, style-src, style-src-elem, connect-src.

CORS — API Related

When the page and controller live on the same server, CORS does nothing — you don't need it. It matters for RESTful APIs where the back-end server differs from the front-end server: you set CORS on the API to define which domains are allowed to read its responses from browser JavaScript.

CSRF — Form Related

The CSRF token defends form submissions. The attack doesn't work when the attacker would need both the session cookie and the CSRF token — the token is what the forged cross-site request can't obtain.

OAuth 2.0 + OpenID Connect

  • Full auth flow (OAuth 2.0 + OIDC):
    1. User authenticates at /connect/authorize → returns a code, given redirect_uri + client_id + scope openid & role.
    2. /connect/token → returns access token + ID token, given client_id + client_secret + code + redirect_uri.
  • Solely OAuth 2.0 (machine-to-machine):
    1. Access token = client_id + client_secret.
    2. Requests carry Bearer + access token — no user, no ID token, no SSO.

GraphQL Introspection

Handy queries to explore an unfamiliar schema:

{ __schema { queryType { fields { name } } } }
{ __schema { types { name } } }
{ __type(name: "ContentItem") { fields { name } } }

Related Vocabulary

  • SLA → customer-facing (external, sometimes internal).
  • OLA → internal, between teams.
  • SLI → the metric you measure (e.g. availability of 2xx responses, uptime %, latency).
  • SLO → the target for an SLI over a period — your reliability promise to yourself.
  • Secret management (e.g. HashiCorp Vault) → secret rotation and audit trail.
