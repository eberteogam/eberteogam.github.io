Engineering Notes — MATLAB / Simulink

  • Monte Carlo runs use Simulink's Multiple Simulations feature (Simulation tab). Above ~100 sweeps, containerize with Docker — each sim is roughly 0.5 s.
  • parsim vs parfor: with parsim, if a single simulation in a 2,000-run sweep crashes, the error is captured and the rest of the batch continues; with parfor, a single error can halt the entire loop. That's why the sweep harness uses parsim.
  • Variable precedence when the same name exists in several places — the more local/explicit one wins: SimulationInput variables (per-run, via in.setVariable(…)) → Model Workspace → Data Dictionary (.sldd) → MATLAB Base Workspace.
  • Physical signals: Transform Sensors provide x/y/z, each needing a PS-Simulink Converter. Six degrees of freedom: Px/Py/Pz positions plus pitch/roll/yaw on the spherical primitive.
  • Model hierarchy: parent–child structure via Model reference blocks — double-click the canvas and type Model in the quick-insert box.
  • Handy CLI: simscape (opens the library), smnew (blank model from the default template), slbuild('Model'), license('test','Simulink_Coder') / 'EmbeddedCoder' / 'Simulink_Compiler' (the wrapper that exports to Java .jar / .NET .dll), and set_param(gcs,'ReturnWorkspaceOutputs','off') to disable OUT in the To Workspace block.
  • Capture envelope parameters for the docking sweep: capture_radius_m = 3, max_offset_m = 1, max_speed_mps = 0.05.
