ServiceNow IDE & Fluent

  • Fluent develops app metadata in .now.ts; TypeScript handles imports/integration. Repositories need a package.json and now.config.json.
  • Switch SDK versions with sn_glider.default_to_bundled_sdk. The IDE can clone from git or convert existing app metadata to Fluent.
  • File anatomy: index.now.ts defines tables; src/server/* holds server-side metadata — BRs, script includes, scheduled jobs run as server-side node modules; client side lives in src/client/.
  • Create the metadata first when building an app — otherwise you won't know the required key: value fields Fluent expects.
  • To convert an app: command palette → Convert an app, then choose file-by-file or right-click → Convert Directory to Fluent. Converted files land in fluent/generated.

Migration: App Repository vs Update Sets

  • Application Repository mode: System Applications > My Company Applications → Publish to My Application Repository; install on another instance from the same menu (Not Installed). Prefer this over Update Sets when an app goes through multiple development phases — versioning is tracked, and scoped apps become available to any instance in the org at any version.
  • Update Sets: no version tracking. When changing app scope, change the sys_id within the customer set and the current instance. To see which tables sync with Customer Updates: Dictionary, filter attributes = *update_synch — true means included; absent/false means records aren't synced.
  • Migration planning notes: pull only last year's closed incidents into a new instance (enough for KPIs); new and active legacy incidents will need their workflows rebuilt as flows in the new instance; any API modification is a high-risk factor; deploy dev → QA when a sprint completes.
  • Fix Forward: never back out an update set from production — create another update set and move it forward.
  • Data-seed templates can be created with the toggle template bar.

ATF — Automated Test Framework

  • Focus ATFs on economic impact: ACLs, domain separation, encryption.
  • Templates exist: Quick Start Tests by scope and feature, and the NowCreate Asset Test template for architecture.
  • Use a pipeline between QA instances with Suites as the steps.

Process Mining

An app that analyzes flow/process data to visualize it — surfacing bottlenecks and improvement opportunities. The flow is generated from audit-log data based on how the project is set up. Three ways in:

  1. Point it at a table and the fields of interest (e.g. Incident + "State" for the last year) and run — the diagram builds automatically from changes to the chosen field.
  2. From a KPI → run Process Analysis → set dates and use case → Workbench → Process Mining.
  3. From a report or table → right-click → Launch Process Mining → set filters → nodes are created → the Insight tab hosts opportunities, each with analytics insights and clusters.
  • Workspace flow: Create project → choose table → filters/conditions → parameters → Mine. Filtered data goes through an ML process (same infrastructure as Predictive Intelligence) that generates the nodes.
  • No AI license is needed to run mining; enabling Analysis (an AI feature) improves performance.

KCS — Knowledge-Centered Service

  • Start with stakeholders — who's involved — and a governance plan.
  • Implementation: build a knowledge-sharing culture, define roles and responsibilities, set goals and metrics, and map process/workflow — start where performance is lowest.
  • KM rollout: get clear ideas and process flow before setting up technology; clean your knowledge bases before moving them; keep a clear governance structure (the right people accessing the right content in the right context — knowledge workflows help).
  • Ensure resources can handle the 30-day stage; solve questions in a timely manner and document new updates; measure metrics — how it helped, the boost, the numbers.

Service Portal Internals (AngularJS)

  • The Portal runs AngularJS with Angular UI Bootstrap (different from regular Bootstrap). ui.bootstrap is recognized by default; the original library is deprecated, and the version your portal uses depends on its configuration — inspect the Network tab filtered by bootstrap or angular and use the URL to find the sys_id in your instance. Useful component: typeahead.
  • GlideRecord bypasses ACLs; GlideRecordSecure (its subclass) respects them.
  • Portal > Theme: you can create multiple CSS Includes that override the default UI Bootstrap precedence on html, body.
  • Key tables: sp_instance — where a widget is used, on which page; sp_log — which pages are actively in use (page + portal + lots of other data).
  • DOM manipulation is not supported in the Portal — when the Portal first shipped, client-side DOM manipulation caused a great deal of problems.
  • UI Builder (Next Experience) targets internal fulfillers working requests/incidents/cases/approvals; the AngularJS Portal targets internal/external requesters.

Agile & Project Delivery

  • Story description: As a <who>, I want <what>, so that <why>. Acceptance criteria: Given <pre-conditions>, when <action>, then <expected results>.
  • Planning & tracking: Agile Development > Themes; Project > Projects > All; or a project's Related Links → Agile Planning and Tracking (VTB + backlog + tracking, 3-in-1). A theme is what multiple stories and epics have in common. Scrum itself is just the board planning/tracking (Story, Epic, Theme, Backlog).
  • Execution types: Waterfall includes tasks (StartNow methodology); Hybrid includes tasks and stories, and shows the Agile Planning & Tracking link.
  • Daily standups: 10 people max, three questions — yesterday, today, blockers.
  • Completed = all tasks of a story done; Done = the Product Owner approved the story. Sprint retrospective after every sprint: what went well, where to improve. HealthScan (now OOTB) checks adherence to technical leading practices at the end of every sprint.
  • Architecture flows from the Statement of Work: Initiate → Plan (SOW) → Execute (Agile) → Deliver (QA testing) → Close. If a big feature (e.g. mobile view) isn't in the SOW, you can't roll it back in — either raise a change request or write a separate SOW.
  • On a defect: ask whether it meets the acceptance criteria; if it does, it's an enhancement, not a defect.
  • Hypercare = the follow-up plan after promoting to production (run ATF, then CI/CD; if something fails, fix forward). Close projects with a session on budget, time, feedback, and next-sprint/future vision.
  • Methodologies: StartNow (originally SN-projects-only), SIM (partner engagements led by ServiceNow), NowCreate (available to all). Work under >Projects for VTBs so SCRUM can be followed.

LDAP, Import Sets & Transforms

  • LDAP integration uses standard import sets and transform maps. To populate the LDAP server field on user records, create a field map with a source script: return source.sys_import_set.data_source.ldap_target.server;
  • Creating an LDAP server requires a MID Server attached to it (and the MID must be validated). Reference links let you test the connection and browse/restrict returned nodes.
  • Excel ↔ table mapping: Import Sets > Load Data → Create Transform Map; then LDAP OU Definitions > Data Sources > Transforms > Table Transform Maps > Mapping Assist.
  • RTE (Robust Import Set Transformers) load data into one or more tables. In transform scripts you can also declare CI relationships directly: return "Depends on::Used By";
  • MID Server: the bridge between the instance and the internal network — WMI for Windows, SSH for Unix, SNMP for switches/printers.

Scripting Conventions

  • Business Rule: (function executeRule(current, previous) { … })
  • UI Action: (function executeAction(current, action) { … })
  • Transform Map: (function transformRow(source, target, map, log, isUpdate) { … })
  • UI/Data Policy example — normalize a phone field: var phone = g_form.getValue('phone').replace(/\D/g, ''); g_form.setValue('phone', phone);
  • Catalog client scripts: onChange and onLoad are void; onSubmit must return a boolean.
  • In classic forms g_form.getControl('FN') returns the actual DOM element; in Service Portal / Catalog items it returns a wrapper object, not the DOM.
  • A record producer can be created straight from table data → Related Links: Add to Service Catalog.
  • From the Tim Woodruff book: ServiceNow runs JS on Mozilla Rhino and executes as ES5 (even where ES6 syntax appears). Prefer the OOTB getValue/setValue over grInc.field_name (which touches the GlideElement object directly) — except for journal fields, catalog variables (append toString()), and dot-walking, where direct access applies. Never dot-walk more than three layers.

Performance Practices

  • Avoid Flow Designer for hot paths. Its underlying architecture creates complex context records in heavy tables, updated on every I/O action — a script is always faster than a flow. When you do use flows, put the logic in Script Actions (bonus: flows currently have no version history).
  • Use gs.debug, not gs.log — every log line is a record in a very heavy table. Errors and warnings: yes, log those.
  • For nested queries, approach it like an API application (headless design).
  • M2M tables: cascade-delete the references so no orphan data survives.
  • Deleted records: sys_audit_delete, filter sys_id by Document Key. Node status: SN-utils /stats.do.

Platform Miscellany

  • VTB: Blocking = a dependency task precedes this one; Stage = ready for deployment; Backlog = queued. Background = a cmd/bash-like console directly on the instance.
  • Workflows: to find which workflow executed on a record — its XML view's <context> tag, or Related Links.
  • ITSM vs ITIL: ITSM is the process behind the form flows (justification, implementation plan, risk/impact, backout, test plan) — the business layer for submitting/approving changes, handling incidents, documenting rollback. ITIL is the vocabulary (standard/normal/emergency change).
  • KPI: a measurable value used to judge performance — same meaning everywhere; the subject changes per module (see the CMDB & CSDM notes).
  • Enterprise Architecture is built on top of Application Portfolio Management / EA data: cmdb_ci_business_app, cmdb_ci_service_auto, cmdb_ci_appl.
  • Now Assist Analytics: Subscription Management gives a high-level view of users across platforms.
  • Now Support: access requires the NS Contributor role (different from the University role), managed through Customer User Access Management. Testing lives in the QA instance (not prod): unit, user-acceptance, integration, regression, penetration.
  • Platform security services: ServiceNow Vault (encryption — how cloud data is protected, shared, and restricted to authorized users), Code Signing & Circle of Trust (extends to the MID Server with signing and validation), Log Export Service (forwards logs to Hermes/Kafka to feed the customer's log-analytics systems).
  • Benchmarks can be created, but avoid them for on-prem, Express, and federal customers.
  • Foundational table = core data shared across multiple tables (users, groups, locations). A Service Catalog item = pre-defined, bundled goods/services from IT or other departments; a CI = something you monitor, manage, measure, track.
